## 2. Dataset Provenance, Statistics & Partition Integrity

### Source Dataset Details
- **Hugging Face Identifier:** [`goendalf666/sales-conversations-instruction-base`](https://huggingface.co/datasets/goendalf666/sales-conversations-instruction-base)
- **Source Revision:** `3d723c68dd3b6ac3c4c0ae021a2d3ab908c4409a`
- **File Format:** Apache Parquet (`train.parquet`, 4,782,593 bytes)
- **SHA-256 Checksum:** `0a3d253771df4879856be8ff50ea0032a939354440a0ff2ed14197b463a39398`
- **Raw Row Count:** 20,940 rows

### Preprocessing & Normalization Findings
1. **Synthetic Inflation Discovery:**
   - Analysis of the raw Parquet revealed that the 20,940 rows were generated by expanding ~1,744 base dialogues turn-by-turn (an average of 12 turns per conversation).
   - Performing a random row-level split would have contaminated validation and test sets with 90%+ overlapping dialogue history from the training set.
2. **Conversation-Level Grouping:**
   - Preprocessing grouped all turns by their root conversation ID before allocating them to splits.
   - Resulting splits:
     - **Train:** 1,338 conversations (14,885 turns, 75.9% of turns)
     - **Validation:** 167 conversations (1,775 turns, 9.0% of turns)
     - **Held-Out Test:** 168 conversations (2,956 turns, 15.1% of turns)
3. **Leakage Verification:**
   - An independent script verified that `trainValLeak = 0`, `trainTestLeak = 0`, and `valTestLeak = 0`. Not a single conversation root appears in more than one split.

### Licensing & Legal Status
- **Source Model:** Synthetic dialogue generated via `gpt-3.5-turbo` using the `salesGPT_foundation` repository.
- **License Status on Hugging Face:** Unspecified.
- **Audit Recommendation:** Under OpenAI's terms of service, synthetic outputs from GPT models cannot be used to train models that compete with OpenAI services. For internal company use and private enterprise deployment, this data is acceptable, but it should not be commercialized as an open-weights standalone model.

## 4. Path to Completing SFT Training (Ready for Execution)

All prerequisite engineering is completed. To execute full GPU fine-tuning:
1. Export `data/training/ess-sales/train.jsonl` and `validation.jsonl` to a GPU instance (e.g., Google Colab with free T4 GPU, RunPod, or AWS `g5.xlarge`).
2. Run:
   ```bash
   pip install torch transformers peft trl datasets bitsandbytes accelerate
   python scripts/train_lora.py \
     --base_model "meta-llama/Llama-3.2-1B-Instruct" \
     --train_file "data/training/ess-sales/train.jsonl" \
     --val_file "data/training/ess-sales/validation.jsonl" \
     --output_dir "artifacts/ess_llama3.2_lora_converged" \
     --epochs 3 \
     --batch_size 4 \
     --lr 2e-4
   ```
3. Convert the resulting LoRA adapter to GGUF format and import into Ollama using `scripts/Modelfile`.
